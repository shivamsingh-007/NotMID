01 · Truth model

What exists—and what does not.

A file is not a feature, a router is not a secured service, and a unit test is not production evidence. The ledger now uses those distinctions consistently.

Verified foundation

  • Patient, clinician, and admin Next.js shells compile on the current Active LTS line.
  • FastAPI passes lint, type-check, and behavioral suites with 90 tests passing and four explicit real-model integration skips.
  • Readiness checks real Postgres, MongoDB, and Redis connectivity and returns 503 when unavailable.
  • Compose and CI configuration parse; local Kafka addressing is valid for host and container clients.
  • Hindi hospital-noise proxy WER is 14.21%; spontaneous Indian-English WER is 6.36%. Patient voice review and touch fallback compile in the production kiosk.

Still a production boundary

  • No Clerk signature, issuer, audience, key-rotation, or webhook verification is wired.
  • No Postgres repositories, migrations, durable triage flags, transactional outbox, or durable audit implementation exists.
  • No tenant-isolation, facility-scope, consent-policy, or break-glass integration evidence exists.
  • Voice Redis/Kafka/S3 adapters exist but lack deployed integration proof; vLLM, Elasticsearch, and the durable Postgres outbox remain unimplemented.
  • No full Compose startup, browser E2E, accessibility, load, security, backup, or deployment proof exists.
02 · Remediation ledger

Twenty-nine repairs that changed the risk.

Filter by original severity. Each card states the defect found in the OpenCode output and the concrete change retained in the repository.

SEC-01Critical

Synthetic clinical APIs looked deployable

In-memory patient, encounter, consent, audit, AYUSH, FHIR, session, and development-token routes were included by default without real Clerk or persistence.

RepairedAll business routers now require explicit ENABLE_DEMO_ROUTES=true; default startup exposes health only.
SEC-02Critical

Credentialed wildcard CORS

The API allowed every origin, method, and header while enabling credentials—an unsafe and browser-incompatible policy.

RepairedExplicit development origins, limited methods and limited request headers; cross-origin credentials disabled.
DEP-03Critical

Frontend baseline carried high advisories

All three apps used a broad Next.js 14 range; dependency resolution reported five high-severity findings per application.

RepairedNext.js 16.3.3 Active LTS, React 19, fresh lockfiles, and zero known npm audit vulnerabilities.
OPS-04High

Readiness checked imports, not dependencies

/readyz returned “ok” when client libraries existed even if every datastore was offline.

RepairedBounded async ping probes, per-dependency results, cleanup, and HTTP 503 on any unavailable required dependency.
CI-05High

CI executed from the wrong directory

Workflow commands assumed apps/ lived at repository root; the project actually lives under patient-case-taking-platform/.

RepairedJob working directories now match repository layout and commands match the declared Python and Node projects.
PY-06High

Python project could not install

The declared setuptools backend was not importable, so a clean editable install failed before tests or type checks.

RepairedStandard setuptools.build_meta backend plus a verified dev installation.
WEB-07High

No reproducible frontend dependency graph

Dockerfiles and CI used inconsistent install commands while no package lockfiles existed.

RepairedFresh per-app lockfiles, npm ci in CI and containers, consistent Active LTS dependencies.
WEB-08High

Kiosk could not survive a production build

A server component passed an event callback into a client component, violating the React Server Component boundary.

RepairedThe interactive landing surface is explicitly client-side and persists language choice locally.
A11Y-09Medium

Interactive markup nested a button in a link

The kiosk wrapped button elements with anchors, producing invalid interactive nesting and ambiguous keyboard behavior.

RepairedLinks receive a shared action style directly; form buttons remain semantic buttons.
CTR-10Medium

Containers were inconsistent and privileged

Only one app used standalone output; runners varied, copied full dependencies, and ran as root.

RepairedStandalone output for all apps, Node 22 builders, minimal runtime copies, and non-root runtime users; API is non-root too.
EVT-11Medium

Kafka advertised one unusable address

The broker told host clients to connect to the container hostname, so localhost connections would fail after bootstrap.

RepairedSeparate internal and external listeners with the API using the internal broker address.
DOC-12Medium

The ledger called prototypes “complete”

Phase 1, auth, persistence, audit, FHIR, and CI were marked complete based mainly on file creation. A second ADR tree duplicated canonical decisions.

RepairedEvidence-based status vocabulary, explicit limits, and one canonical ADR location.
AI-13Critical

ASR upload discarded the patient’s audio

The multipart smoke request looked real, but the endpoint accepted no file parameter and always transcribed generated zero bytes.

RepairedThe REST contract now consumes the uploaded file, validates type, emptiness and size, and returns bounded provider failures.
AI-14High

Browser audio chunks formed a corrupt stream

Every processor callback emitted a new WAV header and the API concatenated those files; the browser also labelled native-rate samples as 16 kHz.

RepairedThe kiosk downsamples to 16 kHz PCM16, preserves message ordering while the socket connects, and the API creates one valid WAV container.
AI-15High

Model scripts executed during test discovery

Pytest collection could start Uvicorn, download large gated models, consume GPU memory, write fixtures, or wait ten minutes.

RepairedReal-model and subprocess suites require explicit environment flags; default CI stays deterministic and side-effect free.
AI-16High

Clinical confidence values were invented

ASR and OCR returned hard-coded 0.92 and 0.90 scores even when the provider response exposed no calibrated confidence.

RepairedConfidence is nullable and only populated when a provider supplies a real score.
AI-17High

OCR configuration was ignored

OCR_PROVIDER=mock still instantiated PaddleOCR-VL, forcing heavyweight dependencies into demos and smoke tests.

RepairedThe registry now honors configuration. Routine documents use PP-OCRv5; the 0.9B vision-language pipeline is an explicit complex-layout fallback.
API-18Medium

AI boundaries were unbounded and leaky

WebSocket audio grew without limit, base64 OCR accepted malformed or oversized payloads, and raw provider exceptions were returned.

Repaired15 MB audio and 10 MB image ceilings, strict base64 validation, typed media allowlists, and sanitized 503 responses.
PH4-19High

Voice could not degrade safely

No microphone diagnostic, ordered end-of-stream contract, transcript correction step, unsupported-language guard, or reliable touch fallback protected patient progress.

RepairedDevice checks, ordered PCM16 delivery, cumulative partials, editable confirmation, clarification signals, and explicit touch fallback.
PH4-20Medium

Latency and accuracy claims lacked a cohort

Single fixture timing could not establish Hindi/English behavior in Indian hospital conditions, and the original p95 calculation understated small-sample tails.

RepairedProvenance-bearing Hindi noisy, 5 dB hospital-ambient proxy, and spontaneous Indian-English manifests; nearest-rank p95 and explicit proxy limitations.
PH5-21High

Clinical dialogue had no approved provider boundary

A future-model architecture was documented, but no bounded, replaceable task contract could prove safe behavior without downloading weights or sending patient text externally.

RepairedVersioned Pydantic dialogue and summary contracts route only to an offline deterministic mock; unsupported providers fail closed.
PH5-22High

Voice answers did not change the interview

Confirmed transcripts advanced a fixed form, so voice capture and the clinical dialogue service remained disconnected.

RepairedThe assisted route sends each confirmed transcript under the returned SOCRATES domain and renders the next mock-provider question.
PH5-23Critical

Warning symptoms could remain inside routine questioning

A patient-facing assistant needs a deterministic interruption that is perceivable without relying on colour, animation, or visual attention alone.

RepairedDeterministic rules bypass SOCRATES, move focus to an assertive bilingual alert, hide internal rule identifiers from the patient, and direct immediate staff escalation.
PH5-24High

Generated text lacked an explicit rejection path

Showing an AI-authored clinical draft without a clear reject state risks implying that it already belongs to the medical record.

RepairedPatient confirmation remains editable, and the clinician can edit, sign, or reject the unsigned draft; rejection explicitly records that nothing was signed.
OPS-25Medium

The Compose override described a different application

The automatically loaded override tried to run the Python API as Node, mounted nonexistent paths, and excluded the shared design-system package.

RepairedFastAPI reload and all three Next.js development mounts now match the repository. Phase 5 explicitly requires no vLLM service, weights, GPU, or external model API.
PH6-26Critical

Two warning-rule authorities could disagree

The legacy rules engine and the Phase 5 LLM ontology each owned separate red-flag terms, IDs, and behavior.

RepairedPhase 5 dialogue and summaries now call one canonical prototype evaluator; the duplicate LLM warning table was removed.
PH6-27High

Triggered rules lacked review metadata

Earlier results did not carry a rule version, ruleset version, owner role, explanation code, approval status, or source evidence paths.

RepairedImmutable rule results now expose stable versions, triage-nurse ownership, controlled explanation codes, path-only evidence, and an explicit prototype-only status.
PH6-28High

Rule silence had no safe contract

An empty result could be misread as a routine triage classification even though it only meant that configured rules did not match.

RepairedThe evaluation contract returns no_configured_flag plus no_match_is_not_safe_or_routine=true; inputs and evidence keys are bounded.
PH6-29Medium

Internal rule IDs appeared in emergency copy

The patient alert displayed implementation identifiers that added anxiety without helping the patient call staff.

RepairedThe accessible emergency state now says routine questions are paused while rule IDs remain in staff/API evidence only.

06 · Production boundary

The next work is not more scaffolding.

The safest sequencing is identity and durable clinical truth first, then asynchronous model workflows. RAG is not required for the initial case-taking product.

No RAG
for V1.

Structured intake, deterministic red-flag rules, document timelines, and clinician-edited summaries can ship without a retrieval-generation layer. Add semantic retrieval only after access-filtered search has a measured clinical use case and evaluation set.
