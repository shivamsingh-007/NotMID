# Messaging Module

MVP: Celery with Redis transport, PostgreSQL durable job state/outbox, bounded retries and dead-letter inspection. Scale stage: Kafka-compatible messaging through managed Kafka or Redpanda, schema registry, retry/dead-letter topics, replay tooling and lag monitoring. Local and externally eligible model requests use separate topics and provider-specific worker bulkheads; completed/failed results use one normalized contract. Admission control bounds queue age/backlog, so the broker is not an unlimited overflow buffer. Both stages use the versioned reference-only envelope in `docs/contracts/EVENT-CATALOG.md`.
